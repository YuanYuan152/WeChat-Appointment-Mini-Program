# 页面访问流程说明

## 概述

本应用采用**首页优先**的访问策略，用户可以直接访问首页，只有在需要登录功能时才会跳转到登录页面。

## 页面访问逻辑

### 1. 首页 (默认页面)
- **路径**: `/pages/index/index`
- **访问方式**: 直接访问，无需登录
- **功能**: 展示应用主要内容，用户可以浏览和了解

### 2. 登录页面
- **路径**: `/pages/auth/login`
- **访问方式**: 仅在需要时跳转
- **触发条件**:
  - 点击个人信息页面的"立即登录"按钮
  - 点击需要登录的功能（如意见反馈）
  - 用户主动选择登录

### 3. 个人中心页面
- **路径**: `/pages/user/profile`
- **访问方式**: 通过底部导航栏访问
- **状态**:
  - **未登录**: 显示登录提示和登录按钮
  - **已登录**: 显示个人信息和功能列表

## 用户流程示例

### 场景1: 新用户首次访问
1. 用户打开应用 → 直接进入首页
2. 用户浏览首页内容
3. 用户点击底部"我的" → 进入个人中心
4. 个人中心显示"请先登录查看个人信息"
5. 用户点击"立即登录" → 跳转到登录页面
6. 用户完成登录 → 返回个人中心
7. 个人中心显示用户信息和功能列表

### 场景2: 已登录用户访问
1. 用户打开应用 → 直接进入首页
2. 用户点击底部"我的" → 进入个人中心
3. 个人中心直接显示用户信息和功能列表
4. 用户可以正常使用所有功能

### 场景3: 使用需要登录的功能
1. 用户在任意页面点击需要登录的功能
2. 系统检测到未登录状态
3. 弹出提示"此功能需要登录后才能使用，是否立即登录？"
4. 用户确认 → 跳转到登录页面
5. 用户完成登录 → 返回原页面
6. 用户可以正常使用该功能

## 页面跳转逻辑

### 登录页面跳转
```typescript
// 从个人中心跳转
const showLoginModal = () => {
  loginMode.value = 'login'
  showModal.value = true
}

// 从需要登录的功能跳转
const handleFeedbackClick = () => {
  handleRequireLogin(
    () => navigateTo('/pages/feedback/index'),
    '/pages/feedback/index'
  )
}
```

### 登录成功后返回
```typescript
// 登录成功后返回上一页
const handleLoginSuccess = (data: any) => {
  isLoggedIn.value = true
  loadUserInfo()
  
  uni.showToast({
    title: '登录成功',
    icon: 'success'
  })
}
```

## 权限控制

### 1. 公开功能
- 首页浏览
- 应用介绍
- 基础信息查看

### 2. 需要登录的功能
- 个人信息管理
- 预约订单
- 咨询记录
- 意见反馈
- 个人设置

### 3. 权限检查
```typescript
import { handleRequireLogin } from '@/utils/auth'

// 检查登录状态并处理
const handleProtectedAction = () => {
  handleRequireLogin(
    () => {
      // 已登录，执行操作
      performAction()
    }
  )

```

## 用户体验优化

### 1. 无强制登录
- 用户可以自由浏览首页
- 不会强制跳转登录页面
- 提供清晰的登录提示

### 2. 智能跳转
- 登录成功后自动返回原页面
- 保持用户的浏览上下文
- 减少不必要的页面跳转

### 3. 友好提示
- 明确说明哪些功能需要登录
- 提供便捷的登录入口
- 登录成功后给予反馈

## 开发注意事项

### 1. 页面访问控制
- 不要强制重定向到登录页面
- 使用条件渲染显示不同内容
- 提供清晰的登录入口

### 2. 状态管理
- 合理管理登录状态
- 及时更新用户信息
- 处理登录失败情况

### 3. 错误处理
- 网络请求失败的处理
- 用户操作错误的提示
- 系统异常的降级方案

## 总结

本应用采用**渐进式登录**策略：
1. **首页开放访问** - 用户可以自由浏览
2. **功能按需登录** - 只在必要时要求登录
3. **智能返回机制** - 登录后返回原页面
4. **友好用户体验** - 清晰的提示和便捷的操作

这样的设计既保证了应用的开放性，又确保了核心功能的安全性，为用户提供了良好的使用体验。
